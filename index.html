关于 Leaf

微光浮影（m.x.） · Alpha version · Slogan：一叶落地，一念生根。🌕

在这个所有人都在构建平台与生态的时代，我们要做什么？

启发性问题，帮助我们预防迷失方向，忘记初心

  • 要做一款无 AI、0 打扰，不会让用户觉得这个东西很烦、不想用的产品。
  • 要做一款零付费、开源的产品，不要让用户掏钱，或者每天担惊受怕怕我们扣费，让用户不信任我们的产品。
  • 让有志之士们可以随时 fork 我的项目对其加以改进，因为我很多的存货，也都是在开源社区学到的。
  • 要做一款 "Web + 云端优先"，让老设备也可以随心用，并保持四端（桌面端、Pad 端、移动端与网页端）统一的使用体验，让用户用起来安心且不麻烦的产品。
  • 坚持 "Less is more" 的理念，做一个工具而不是一个平台，即用即走。

我们的同道先辈们都在做什么？

探寻同道前辈们的路径，取其精华，去其糟粕，并以史为鉴

幕布 ｜ 极简化输入，结构化思考，可视化呈现

值得学习的地方：

  • 保证四端（桌面端，Pad 端，移动端与网页端）的使用体验完全统一，让用户易上手，不会绕圈子。
  • 支持 Markdown 语法，带来极简化且高效的输入。
  • 以大纲笔记为主体，锻炼结构化思维，让你想得更清楚，理解更透彻。

不值得学习的地方：

  • 除主导的大纲笔记以外，幕布还支持思维导图模式。这无疑很高效，但我们不想做 All in one，我们坚持 "Less is more"。
  • 拥有高级版（会员订阅）功能，虽说免费用户不至于用不好，但功能还是有受限。

熊掌记（Bear）｜ 优美设计，容易上手，可惜锁苹果生态

值得学习的地方：

  • 纯文本 & Markdown 优先，加上其隐藏语法的纯净排版体验，而不会被符号所干扰。
  • 明确的隐私价值观姿态，让用户知道笔记只属于自己，不必担心会被窥探、被私自上传他人服务器或数据被售卖，让用户对产品产生信任。
  • 0 打扰的专注模式，让用户在打开的一瞬间就 Focus on writing，专注于记录，不被其他元素所打扰。
  • 轻量的标签组织，让用户可以灵活地归类卡片，而不必被困在传统同类产品的文件夹层级里迷路。
  • 支持纯文本的开放格式，让用户的笔记随时迁移，而不必被锁在某个平台里。

不值得学习的地方：

  • 有订阅服务 Bear Pro，让同步、主题、加密、导出等基础能力均需付费，从而让部分经济不理想的用户，对其产生不信任之类的情况。
  • 锁在 Apple 的 "花园生态" 内，产品只能在 Apple 产品上跑，云同步也依赖 iCloud，让笔记离开了本地，对非 Apple 生态用户想入坑造成极大困扰。虽已有网页版在内测状态，但正式版公布后，仍需付费才可使用网页版。
  • 非会员用户功能受限。免费用户能写，但同步、主题、导出等上层功能还是受限。免费用户不至于用不好，但功能还是没法用全。
  • 支持维基链接 / 反向链接，追求个人 Wiki 与知识管理，范围蔓延向平台化，违背了 "Less is More" 的理念。
  • 拥有 30 余款主题与个性化图标，追求 cosmetic 付费墙，是有专注于记录本身，但也在堆砌外观。

flomo（浮墨笔记）｜ 卡片式笔记，极简记录灵感碎片，Less is more

值得学习的地方：

  • 卡片式笔记，能随时随地把自己的灵感碎片记录下来。
  • "Less is more"，让用户在打开的一瞬间就可以 focus on task，专注于记录上面，而不会被其他内容打扰。
  • 把 flomo 变成一个给自己看的微博或者 Twitter，想记啥都可以。它确实配得上「记录想法的川流」的「思维工具」这个称号。

不值得学习的地方：

  • 不支持 Markdown 语法，因为其主打卡片式笔记 + 极简记录，但这会让部分群体（包括我在内）感觉稍微有点不太趁手。
  • 拥有会员以及 AI 功能，我们相信有人会需要这些功能，但我们不想做一个让用户不信任的产品。

为何选择 "Web + 云端优先" ？

明确我们所坚持的理念，防止违背初心

选择 "Web + 云端优先" 是为了照顾到使用旧设备的朋友们，且达到不限制生态的目的，并尽量少占用户设备的空间。当然，这并不代表我们会排除开发独立 App 的可能。

我们对于 AI 的态度

描述清楚：为何我们选择做 Leaf 这样一款无 AI、纯粹专注记录与回顾的「思维工具」

我们不是不知道 AI 是当前的大趋势，我们也承认，AI 在某些方面确实很优秀。但是，市面上已经有很多加入 AI 并且成功的例子，例如 flomo、Notion 等成功又好用的产品。我们不认为，这个市场上还需要我们再来加入 AI。

那我们要做什么？

  • 让我们先来想个问题：你有没有发现，你现在好像越来越不爱独立思考了？
  • 给你举个画面吧：当老板给你发一串很长很长的 PPT，你会选择怎么样？是不是一键扔给 AI，让它给你总结一下，顺便还要加上一句："总结成你看得懂的样子"？
  • 这就是目前的情况：我们越来越多的人在熟练地使用 AI。但问题是，我们熟练使用 AI 的方式，却是在外包大脑，让 AI 成为思考的工具，而我们的大脑只负责验收集成果就可以了。这样会让我们越来越懒。
  • 就像我在 flomo 记录的这条 memo 一样：是啊，正因为在这个 AI 时代，我们每个人的思想才格外重要。因为 AI 读过全世界的书，但它缺少属于你独自的那点上下文，这也是为什么我们选择做一个无 AI 的「思维工具」的原因。
  • 当然，我不是什么非常排斥 AI 的人，就连这整个产品，都是用 WorkBuddy 的项目功能进行开发的。但我不希望在这个产品里加入 AI，因为我只是觉得这是一款专注于让你记录和回顾的产品，不需要在这里面加入 AI。况且我作为一个学生党，也没有那么多钱去给你们搭建服务器之类的，还请各位谅解。

Why Markdown？

说明在 Leaf. 中加入 markdown 的原因，并阐述清楚自己的理念

我们知道，有些人可能会对我们在 Leaf. 内加入 markdown 提出质疑，认为这不算 less is more；但我们的理念是在保证 "less is more" 的前提下，方便使用我们的产品的每一位朋友。Markdown 作为目前互联网上使用非常广泛的一种格式，它非常方便。只需要用几个符号，在适应的编辑器或者查看器内，就可以将文档进行黑体、斜体、引用等处理。

并且我们也会提供开关，就像幕布那样，如果不需要 markdown 功能的朋友，可以选择关闭。具体关闭入口需要等产品开发完再公布……

p.s. 我现在才做到 Alpha version，几乎完全不可用…QAQ

Last choice：开源

看似是断自己的路，其实也是在丰富生态

选择开源，其实也是想回馈一下开源社区。因为自己虽说用了像 F-Droid、DeepSeek、Bitwarden 等很多开源社区中诞生的，或者是选择开源的项目，但却从来没有为社区做过实质性的贡献，只是用着他们的产品并且汲取灵感…没有他们，或许就没有现在的我。因此，我决定在 Leaf. 的整个产品开发完成后，将其开源至 GitHub 与 Gitee。也在此提前欢迎各位有识之士：在我将此项目开源后，尽情地 fork 此项目，并且让它变得更好吧！也算是我对开源社区的一点谢意了。

关于数据存储：Leaf 使用浏览器本地数据库（IndexedDB）保存你的笔记，不上传任何服务器。推荐通过本地静态服务器或部署到任意 https 网站后访问；直接以 file:// 双击打开时，部分浏览器（尤其 Safari、移动端）可能禁用本地存储，导致笔记无法保存。部署后体验最佳。
